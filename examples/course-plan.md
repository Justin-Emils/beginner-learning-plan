# 示例：零基础、三周内交一个处理器作业

> 场景：计算机专业本科生，要在三周内完成"五段流水线"课程作业，自评"对系统结构一无所知"。
> 下文的假设表、阶段表、缺口、触发器都来自一次真实使用（个人信息已去掉）。

## 一、水平假设表（先让对方改）

| # | 我的假设 | 你说是 / 不是 |
|---|---|---|
| 1 | 会二进制/十六进制互换，能算 `0x1c = 28` | |
| 2 | 知道"寄存器"是 CPU 内的一组小存储单元 | |
| 3 | 知道机器码是指令的二进制形式，但没手算过编码 | |
| 4 | 没写过汇编，看得懂 `add t0, t1, t2` 大概意思 | |
| 5 | 知道 `lw/sw` 是访存，说不清 `0(t3)` 的含义 | |
| 6 | 时序（时钟周期、"到点才变"）只有模糊印象 | |
| 7 | 没画过数据通路图，不知道 mux 长什么样 | |
| 8 | 能读懂 Python，没写过类为主的中等规模代码 | |
| 9 | 没用过 Ripes / Logisim / Verilog 仿真 | |
| 10 | 每天能投入 1.5–2 小时，周末多一点 | |

**改完之后要做的事**：把"比我原设更低"的条目单独拎出来，写成《起点校准》，并说明它改变了哪些安排。
例如第 6、7 条成立 → 第一天不碰代码，先手画五段与 mux。

## 二、阶段表（学什么 ↔ 产出）

| 阶段 | 学什么 | 产出（看得见的） | 预计 |
|---|---|---|---|
| A | 五段各干什么 | 用自己的话写 300 字"一条 add 的一生" | 1 天 |
| B | 五个 mux 的选择规则 | 手写 5 条指令的 mux 预测，工具核对全对 | 1–2 天 |
| C | 冒险：load-use、分支冲刷 | 在时空图上指出停等与冲刷的位置 | 1 天 |
| D | 跑通现成模拟器 | 一个程序跑出正确结果 + 五个检查点 | 1 天 |
| E | 测试即证明 | 差分比对通过 + 报告里的测试表 | 1 天 |
| F | 写报告 | 可提交的 PDF | 2–3 天 |

## 三、这套材料**没有**覆盖的（缺口）

| 缺口 | 影响 | 补法 |
|---|---|---|
| Verilog / RTL | 若作业要求硬件实现，只做模型不够 | 复用已有仿真流程，按同一套信号名生成 |
| 时序分析 | 报告"为什么这样分段"讲不深 | 定性一段：最慢段决定时钟周期 |
| Cache / 虚拟内存 | 本次不考 | 跳过 |
| 分支预测、乱序 | 加分项 | 报告扩展一节写 100 字 |
| 同名概念在教材里的差异 | 容易混 | 列一张三行对照表 |

## 四、汇报触发器

| 触发 | 发什么 |
|---|---|
| 完成一个小练习 | 三行：做了什么 / 卡在哪 / 用时 |
| 卡住 > 40 分钟 | 报错原文 + 改到哪一步 + 猜测 |
| 每阶段结束 | 勾选清单 + 三问自答 |
| 连续 2 天没动 | 直接说"停了"，砍计划而不是硬扛 |

## 五、验收三问（每阶段）

1. 删掉这段会怎样？
2. 需求改成 X，你要改哪一行？
3. 你卡在哪里，最后怎么解决的？

## 六、减法预案

| 顺序 | 砍什么 | 后果 |
|---|---|---|
| 1 | 截图从 5 张减到 1 张 | 少直观证据 |
| 2 | 扩展章节压到半页 | 少加分 |
| 3 | 程序从 5 个减到 3 个 | 覆盖略窄 |
| 4 | 随机测试从 200 组减到 20 组 | 说服力下降，报告里要说明样本量 |

**不能砍**：现场解释 mux 的能力、与参考实现的比对、手册引用。
