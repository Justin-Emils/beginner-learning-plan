# beginner-learning-plan

> 把"我想学 X"变成"今天做哪几件具体的事"，并且**保证学习者真的动手**。

A skill for turning a vague "I want to learn X" into an executable, day-level study plan
for a beginner whose self-assessment is unreliable — with real course material, explicit
gaps, visible output per stage, and acceptance checks that cannot be faked by "watching videos".

---

## 它解决什么问题

| 症状 | 这个技能的对策 |
|---|---|
| 计划写了三页，学习者三周后消失 | 一屏「当前任务」+ 汇报触发器 |
| 学习者说"我都懂了"，一动笔就卡 | 水平假设表（由他改）+ 三遍法 + 验收三问 |
| 按教程学完了，项目还是做不出来 | 练习必须挂在项目上；每阶段要有看得见的产出 |
| 学到一半发现教程根本没讲需要的部分 | 强制标注教材缺口，并给补课清单 |
| 时间永远不够 | 估算口径（写码只占 30%，现实 ×1.5）+ 减法预案 |

## 产出物

- **水平假设表**：8–10 条猜测，留一列让学习者自己改（自评通常偏高，但必须由他改）
- **阶段表**：学什么 ↔ 项目哪一步 ↔ 看得见的产出 ↔ 周数
- **教材缺口**：这套课**没有**覆盖什么，什么时候补
- **一屏当前任务**：现在做什么、怎么验、做完汇报哪三行
- **汇报触发器**：什么情况必须说话（卡住 40 分钟、连续两周无进展……）
- **验收三问**：删掉会怎样 / 需求改成 X 改哪行 / 你卡在哪怎么解决的
- **减法预案**：时间不够按什么顺序砍，什么绝对不能砍

## 安装

dsh（技能根是 `~/.dsh/skills/`）：

```bash
git clone https://github.com/<you>/beginner-learning-plan.git
cp -r beginner-learning-plan ~/.dsh/skills/
# 或者保持单一真源，用软链：
ln -s "$PWD/beginner-learning-plan" ~/.dsh/skills/beginner-learning-plan
```

Claude Code：放到 `~/.claude/skills/`（注意：**dsh 不扫描** `~/.claude/skills/`，
两个环境要各放一份或软链）。

放好后在会话里输入 `/skills` 或直接描述任务，模型应能自动召回；
也可显式调用：`skill beginner-learning-plan`。

## 用法

直接说清楚三件事：**要学什么、为了做出什么、现在什么水平**。

```
我想在两个月内做出一个能上线的数据看板，但我只会一点 Python，
前端完全没写过。帮我排一个能真正执行的学习计划。
```

技能会先给你一张假设表让你改，然后才排计划——**顺序不要反**。

## 一次真实的使用记录

用它给一位"对计算机系统结构一无所知"的同学排《计算机系统结构》的五段流水线作业：

1. 先出假设表（"知道二进制换算""没写过汇编""没用过仿真器"……），让对方改；
2. 按真实材料排阶段（读哪一节、跑哪条命令、写哪三句话）；
3. 标注缺口（Verilog、cache、408 题不在课程里）；
4. 给一屏当前任务 + 汇报触发器；
5. 计划落地成 4 份文档，之后十轮迭代都围绕这几份文档推进，而不是每次重新对齐。

结论：真正省时间的不是"排得多细"，而是**假设表 + 一屏任务 + 验收三问**这三件把小步走死。

## 设计原则（压缩版）

1. 先让学习者修正你的假设，不要靠猜
2. 计划落到真实材料（第几集/第几章），不写"学完 XX"
3. 主动标注教材缺口
4. 三遍法：看懂 → 故意改坏看报错 → 关掉教程从空白重写
5. 练习挂在项目上
6. 验收 = 三个问题 + 代码审查，答不上就是没学会
7. 汇报分触发器，不要只说"学完汇报"
8. 一屏「当前任务」，做完即换
9. 估时口径写清（写码 30%、调试 30%、样式 15%、内容 10%、部署 10%、文档 5%；现实 ×1.5）
10. 必配减法预案 + 不可砍清单

## 局限（如实写）

- 需要**真实教材目录**才能排到"第几集/第几章"；拿不到目录时要先要目录，不要编
- 不适合一次性问答：它假设有一段持续数周的学习过程
- 假设表依赖学习者愿意承认"不会"；如果对方敷衍，计划会偏乐观
- 不替代项目本身的技术判断（架构、选型），只管"怎么学会"
