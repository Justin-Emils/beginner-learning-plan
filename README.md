# beginner-learning-plan

> 先评估你的真实水平，经你确认，再排计划、再讲解——讲解里不许出现没定义的词。

A skill that puts assessment before planning: multi-instrument level check → learner
confirms the profile → plan where every item cites the profile → explanations with a
term budget and an explicit "this section assumes you already know…" line → re-assessment
after every stage.

---

## 它解决什么问题

| 症状 | 这个技能的对策 |
|---|---|
| 计划写得挺好，但讲的时候对方一脸茫然 | 先评估，再按画像写讲解（术语预算 + 前置声明） |
| 评估只是"十条假设让你改" | 冷读测试 + 术语盘点 + 复述题 + 置信度，四种手段互相校验 |
| 评估做完，计划还是原样 | 每条计划项必须标注"依据画像里的哪一条"，写不出就删 |
| 讲解里冒出没定义的名词 | 每节新术语有上限，首现必须"定义 + 例子 + 反例" |
| 用"这个你应该知道"开头 | 每节开头强制写"本节假设你已知道：…" |
| 学到中途水平变了，计划没变 | 每阶段复评 + 确认门，画像带变更记录 |
| 计划写了三页，学习者三周后消失 | 一屏「当前任务」+ 汇报触发器 |
| 时间永远不够 | 估算口径（写码只占 30%，现实 ×1.5）+ 减法预案 |

## 流程（顺序不能反）

```
1 评估（四种手段） → Gate A：学习者逐条确认
                        ↓
2 计划（每项标注依据） → 3 讲解（术语预算 + 前置声明 + 分级讲法）
                        ↓
4 阶段验收 + 复评（画像 v1） → Gate B：确认变更 → 回到 2
```

**Gate A 不通过就不排计划。** 用户说"你看着办"= 未确认。

## 产出物

- **画像**：五个维度（术语 / 读码读图 / 工具 / 时序数学 / 元技能）× A/B/C，附结论与变更记录
- **阶段表**：每项后面标"依据：画像里的哪一条"
- **教材缺口**：这套材料没讲什么、什么时候补
- **一屏当前任务**：现在做什么、怎么验、汇报哪三行
- **汇报触发器**、**验收三问**、**减法预案**

```bash
git clone https://github.com/<you>/beginner-learning-plan.git
ln -s "$PWD/beginner-learning-plan" ~/.dsh/skills/beginner-learning-plan
```

Claude Code：放到 `~/.claude/skills/`（注意 dsh **不扫描** 这个目录，两个环境各放一份或软链）。

## 用法

说清三件事：**要学什么、为了做出什么、现在什么水平**。

```
我想两个月内做出一个能上线的数据看板，只会一点 Python，前端没写过。
先帮我评估水平，我确认之后你再排计划。
```

技能会先给一张假设表 + 一份冷读材料 + 一张术语盘点表，让你逐条回答；
确认画像之后，才会出现阶段表和一屏任务。

## 设计原则（压缩版）

1. 画像未确认，不许排计划
2. 每条计划项都要能追溯到画像，追不上就删
3. 每个新术语当场定义；每节开头写"本节假设你已知道"
4. 评估用多种手段，猜对的按不会处理
5. 三遍法：看懂 → 故意改坏看报错 → 关掉教程从空白重写
6. 练习挂在项目上，每阶段有可见产出
7. 验收 = 三问 + 代码审查，答不上就是没学会
8. 每阶段复评，画像变更要留痕、要确认
9. 估时口径写清（写码 30%、调试 30%、样式 15%、内容 10%、部署 10%、文档 5%；现实 ×1.5）
10. 必配减法预案 + 不可砍清单

## 局限

- 需要真实教材目录才能排到"第几集/第几章"，拿不到就先要目录，别猜
- 不适合一次性问答：它假设有一段持续数周的学习过程
- 评估依赖学习者愿意承认"不会"，敷衍的回答会让画像偏高（所以才要置信度和复述题）
- 不替代项目本身的技术判断（架构、选型），只管"怎么学会"
